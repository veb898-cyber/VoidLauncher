## 1. Целевая UX-модель

`VoidLauncher Room ID (ABCD-1234) → associated Tailscale peer → Tailscale IP → Minecraft endpoint`

- `ABCD-1234` — **UI-код комнаты VoidLauncher** (логическая сущность приложения), не обязательно hostname Tailscale.
- Игровой трафик не проходит через ваш backend (P2P через Tailscale, direct или DERP).
- Minecraft не модифицируется (LAN-мир, join по `IP:порт`).
- Tailscale полностью скрыт внутри VoidLauncher (пользователь не видит IP/порт/VPN).

## 2. Разграничение понятий (зафиксировано)

- **VoidLauncher Room** — логическая сущность приложения: код, участники, игровая сессия, состояние.
- **Tailscale Machine Share** — сетевой доступ к конкретной хост-машине (машине владельца).

**Ограничение:** Sharing изолирует доступ к конкретной машине, а не создаёт отдельный
сетевой сегмент для каждой логической комнаты. **Не обещаем**, что две комнаты на одном
ПК автоматически изолированы друг от друга. Комнатная изоляция обеспечивается продуктовым
уровнем VoidLauncher (доступ = доступ к хост-машине), а не Tailscale.

## 3. Модель пользователей и лимитов

**Подтверждено документацией 📚:**
- 1 аккаунт = 1 человек; каждый пользователь — со своим бесплатным аккаунтом.
- Personal (free forever): до 6 пользователей, до 3 ACL-групп, 50 tagged resources,
  устройства без лимита; «playing games with friends» — допустимое использование.
- Лимиты сейчас не enforced; enforcement начнётся «в ближайшие месяцы» (следить).

**Решение MVP:** до 5 друзей как основной сценарий (входит в лимит 6 пользователей).

## 4. Machine Sharing (сетевой доступ к хосту)

**Подтверждено документацией 📚 + локально ✅:**
- Sharing доступен на всех планах (beta); получатель видит только расшаренную машину.
- Приём входящих к любому процессу (Java/Minecraft) на Tailscale-интерфейсе разрешён
  фаерволом (`Tailscale-In`, Program=Any, профили Domain/Private) — локально проверено ✅.
- Quarantine по умолчанию: машина отвечает на входящие, но не инициирует исходящие —
  подходит для Minecraft (гость инициирует).

**Создание инвайта — только admin console (ручной шаг):**
- Инвайты: по email (одноразовая ссылка) или invite link (одноразовый / reusable до 1000);
  неиспользованные живут 30 дней.
- Получатель обязан быть Owner/Admin/IT admin **своего** tailnet.
- Отзыв — вручную в admin console; документированного API для share-инвайтов нет.
- Сужение до портов — через grants/ACL (`autogroup:shared`, `ip: ["25565"]`) 📚.

## 5. History-компоненты VoidLauncher

| Компонент | Обязанности |
|---|---|
| **TailscaleManager** | detect install → silent MSI (официальный + sha256, `msiexec /i /quiet` + `TS_*`, UAC один раз) → статус службы → логин пользователя → poll `status --json` → find peer по room code/hostname → `logout` → `msiexec /x` |
| **RoomStateManager** | генерация Room ID `ABCD-1234`, FSM состояний комнаты host/guest, таймауты, событийная модель |
| **ShareBootstrap** | открытие admin console + руководство (см. §8), мониторинг принятия (появление peer) |
| **MinecraftConnector** | запуск игры, парсинг порта из лога, сборка аргументов join (см. §7) |
| **RoomUI** | код комнаты, статус, кнопки host/join/leave/revoke, подсказки ручных шагов |

## 6. Состояние комнаты (FSM)

**Host:**
`CREATE (Room ID) → SHARE_BOOTSTRAP (ручной шаг: admin console) → WATING_PEER (poll status) → PEER_READY → HOSTGAME (ручной шаг: Open to LAN) → GAME_PORT_KNOWN → ACTIVE → (close room) STOPPED`

**Guest:**
`ENTER_CODE → TAILSCALE_READY → WAIT_ACCEPT (ручной шаг: принятие share-link) → UP → DISCOVERY → IP_FOUND → JOIN (game) → ACTIVE → (leave) STOPPED`

Таймауты на ручные шаги. `leave` игровой сессии НЕ разрывает share-доступ (см. §6 revoke).

## 7. Lifecycle Tailscale и discovery

- **Install** ✅ локально: detect → silent MSI + `TS_*` (hide onboarding/menus, unattended) →
  служба → политики в `HKLM\SOFTWARE\Policies\Tailscale`. UAC — единственный системный запрос.
- **Login** ✅/📚: `tailscale up` → ссылка/QR → вход в **свой** аккаунт (браузер).
- **Discovery peer** 🌐 требует cross-network проверки. Основная модель:
  `VoidLauncher Room ID → associated Tailscale peer → Tailscale IP → Minecraft endpoint`.
  - Реализация-кандидат 1: комнатный peer = единственный «новый» (расш主) peer в
    `status --json` у гостя (sharing показывает одну машину).
  - 🧪 **Временный/экспериментальный**: `hostname = room code` — префикс `HostName`/`DNSName`
    в `status --json`. НЕ основная архитектура: на одном ПК может быть несколько логических
    комнат, а hostname машины один. Используется только как experimental-механизм
    для задач discovery, решение — после cross-network теста.

## 8. Minecraft discovery/compatibility слой

⚠ **Не объявлен production-ready для всех поддерживаемых версий.** Это discovery/compatibility
слой, требующий отдельного тестирования на целевых версиях Minecraft.

- **Host**: запуск одиночной игры/мира → **ручной шаг в игре**: «Открыть для LAN»
  (или `/publish [gamemode] [allowCommands] [port]`, порт в 25565–25575, с 1.19.3 редактируется).
  Парсинг `latest.log` на `Local game hosted on port N` — **экспериментальный**, требует
  верификации по версиям и локаль (возможно, парсить также чат/вывод).
- **Guest**: join по `hostIP:N` — кандидаты автозапуска `--quickPlayMultiplayer "host:port"`
  (1.20.2+) и legacy `--server ip --port port` — оба **на проверку** на целевых версиях
  (формат, приоритет аргументов, совместимость).
- **Фаервол** ✅ локально: отдельного разрешения для игрового процесса не требуется
  (Tailscale-In Allow для любых процессов на 100.x.y.z).

## 9. Игровой трафик

P2P WireGuard через Tailscale (direct или DERP-fallback), через backend (если появится) —
только коды/служебная информация, никогда игровой трафик. 🌐 классификация direct/relay
— только при cross-network тесте; локальный `netcheck` — индикатор 🧪.

## 10. Ручные действия пользователя (по категориям)

**Цель MVP:** после первоначальной настройки максимально убрать ручные действия.

### A. Только при первоначальной настройке (разово)
| № | Действие | Кто | Статус |
|---|---|---|---|
| 1 | Подтвердить UAC при тихой установке MSI | хост/гость | автоматизируется, один раз |
| 2 | Войти в свой бесплатный аккаунт Tailscale (ссылка/QR из лаунчера) | каждый | полуавтомат, первый запуск |
| 3 | (Рекомендуется заранее, не на каждую комнату) создать **reusable share-ссылку** в admin console и сохранить её в VoidLauncher | владелец-host | ручной шаг настройки |
| 4 | Гость: принять share-ссылку в браузере (быть Owner своего аккаунта) | гость | ручной шаг, первый раз на друга; повторно — только после revoke |

### B. При создании новой комнаты
| № | Действие | Кто | Статус |
|---|---|---|---|
| 5 | Если reusable-ссылка не создана (шаг 3) — создать share-инвайт в admin console | владелец-host | ручной шаг (или использовать сохранённую reusable) |

### C. При каждой игровой сессии
| № | Действие | Кто | Статус |
|---|---|---|---|
| 6 | Открыть мир в игре: пауза → «Открыть для LAN» (порт парсится из лога) | хост | ручной шаг в игре (без модификации клиента), парсинг — на верификацию |

Обычный выход из Minecraft и перезаход — автоматика (join по коду комнаты).

### D. При окончательном отзыве доступа (не после каждой сессии)
| № | Действие | Кто | Статус |
|---|---|---|---|
| 7 | Revoke share / участника в admin console (`Machines → ⋯ → Share → Revoke invite`) | владелец-host | ручной шаг, только при закрытии доступа |

**Важно:** `revoke` относится к удалению/закрытию доступа к комнате или участнику,
а НЕ к обычному выходу из Minecraft. При reusable-ссылке доступ сохраняется между
игровыми сессиями — это ожидаемое поведение MVP.

## 11. Lifecycle комнат и доступа (host/join/leave/revoke)

- **Create (host)**: Room ID → share-доступ (reusable или новый инвайт) → ожидание peer →
  порт из лога → ACTIVE.
- **Join (guest)**: код → accept (первый раз) → discovery peer → IP → join.
- **Leave (сессия)**: закрыть игру; share-доступ остаётся (reusable). При желании
  гость может `tailscale logout` — это не отзыв шаринга.
- **Revoke (доступ)**: ручной отзыв в admin console → гость теряет доступ;
  для нового входа — новый инвайт + повторное принятие.

## 12. Известные риски и открытые пункты

- Enforcement лимитов Personal (6 users / 3 groups / 50 tagged) после начала применения 📚.
- 30-дневный срок неиспользованных инвайтов; revoke = повторный ручной цикл.
- Комнатная изоляция — только на уровне приложения (см. §2).
- Discovery (candidate 1 vs 2) — 🌐 тест.
- Minecraft discovery/совместимость (`quickPlayMultiplayer`, legacy args, парсинг порта) — ⚠ на верификацию.
- Cross-network тесты: реальный join друга в мир, direct vs DERP, жизненный цикл share — 🌐 отложены до второго участника.

## 2. Кратко о каждом направлении

### 2.1. Редактор скинов

**Что даёт пользователю:** выбирает аккаунт в карточке на странице «Аккаунты», открывает полноэкранный диалог редактора, импортирует PNG 64×64 или рисует скин на 2D-атласе, видит 3D-превью, загружает скин в Minecraft для Microsoft-аккаунта и экспортирует PNG.

**На чём основано:** уже есть `SkinPreview` на `skinview3d`, загрузка скина через `cmd_change_skin`, кэш heads, bundled default skins, экран Accounts.

**Ключевые границы:**

- Java Edition, формат PNG 64×64, base/outer слои, classic/slim;
- редактор открывается полноэкранным диалогом из карточки аккаунта; отдельная страница не используется;
- импорт PNG 64×64 с компьютера входит в MVP;
- Microsoft-аккаунт — редактирование, импорт, экспорт и загрузка на сервер;
- offline/Ely.by — локальное редактирование, импорт и экспорт, без upload API;
- никакой прямой инъекции скинов в Bedrock;
- постоянные черновики и локальная библиотека скинов в MVP не создаются;
- 64×32 не редактируется и не конвертируется в MVP;
- загрузка только по явному действию пользователя.

**Главный риск:** API загрузки скина и кэш голов. Нужно инвалидировать `heads/<uuid>.png` после успешной загрузки, иначе пользователь увидит старый скин.

### 2.2. Редактор тем

**Что даёт пользователю:** создаёт **одну** собственную тему на основе встроенной, меняет 22 ключевых цвета, видит предпросмотр на реальных компонентах, сохраняет и применяет её, сбрасывает изменения к базовой теме и экспортирует/импортирует JSON.

**На чём основано:** `themeStore` с единственным writer `data-theme`, шесть встроенных тем, 78 CSS-переменных, Liquid Glass как отдельный режим, ранний bootstrap в `index.html`.

**Ключевые границы:**

- MVP — ровно один слот «Моя тема», без библиотеки и списка нескольких тем;
- никакого произвольного CSS и загрузки `.css`;
- только 22 whitelisted токена и валидированные цвета;
- MVP — только тёмные темы;
- Liquid Glass не смешивается с пользовательской темой; после его отключения тема восстанавливается;
- встроенные темы неизменны;
- тема хранится локально; экспорт — способ бэкапа;
- импорт/экспорт JSON, сброс к базовой и отключение темы входят в MVP.

**Главный риск:** захардкоженные цвета вне переменных, 19 `!important` и контраст. Нужен аудит до UI.

### 2.3. Minecraft for Windows (Bedrock)

**Что даёт пользователю:** отдельная страница, которая показывает, установлена ли официальная Bedrock-игра, ведёт в Microsoft Store/trial, запускает установленный экземпляр и (этап 2) показывает миры и делает резервные копии.

**На чём основано:** официальный `Get-AppxPackage`, `IApplicationActivationManager`, package data в `%LOCALAPPDATA%\Packages\...`, локально подтверждённый пакет `Microsoft.MinecraftUWP 1.26.5203.0`.

**Ключевые границы:**

- только официальная установка из Microsoft Store;
- никакого пиратства, обхода лицензии, переупаковки пакета, сторонних сборок;
- не скачивать и не распространять игру;
- не автоматизировать вход в Microsoft/Xbox;
- `custom_skins` — только открыть папку, без записи;
- запуск мира и running state — только после spike.

**Главный риск:** юридические ограничения и хрупкость Windows-интеграции (AUMID, helper-процесс, формат миров).

## 3. Рекомендуемый порядок

### Основной маршрут

1. **Skin Editor MVP** — первый этап. Самый понятный и ограниченный объём; уже есть 3D-превью, загрузка и аккаунты.
2. **Theme Editor MVP** — второй этап. Подготовку (аудит токенов, модель одной темы) можно вести параллельно с skin MVP, но реализацию — после него, с учётом общих изменений UI и локализации.
3. **Необходимые расширенные этапы редакторов** — после обоих MVP: расширения редактора скинов и редактора тем, без которых их нельзя считать полноценно завершёнными. Состав фиксируется отдельно; Bedrock сюда не входит.
4. **Интеграция Bedrock** — в самом конце, только после завершения обоих MVP и необходимых расширенных этапов редакторов. Подробный план Bedrock существует отдельно и в текущую работу не входит.

### Почему skin раньше theme

- Skin MVP не требует рефакторинга глобального CSS.
- Theme MVP выигрывает от аудита, который лучше делать без спешки.
- Оба направления трогают Settings/Accounts/i18n; последовательная реализация снижает конфликты.
- Параллельная подготовка темы допустима, но не должна менять общие UI/i18n-контракты без согласования со skin MVP.

### Почему Bedrock последний

- Порядок зафиксирован требованиями: Bedrock не начинается, пока не завершены оба MVP и необходимые расширенные этапы редакторов.
- Это отдельное направление со своими Windows-интеграциями и юридическими ограничениями; его исследование не входит в текущий этап.

## 4. Зависимости и общие места

### Жёсткие зависимости

Технических зависимостей между редакторами нет. Продуктовый порядок фиксирован: skin MVP → theme MVP → необходимые расширенные этапы редакторов → Bedrock.

### Общие технические зоны

| Зона | Skin | Theme | Bedrock |
|---|---|---|---|
| `Sidebar`/`App` routing | — | — | новая страница |
| `Settings` | — | основная точка входа | — |
| `Accounts` | точка входа | — | — |
| i18n `en.ts`/`ru.ts` | новые ключи | новые ключи | новые ключи |
| Tauri commands | upload/cache | экспорт JSON | detection/launch/worlds |
| CSS/UI | диалог, canvas | токены, preview | карточки, статусы |
| Тесты | image/upload | color/schema | detection/paths |

### Что делать общим

- Новые строки — только через `t()`, `en.ts` — source of truth.
- Новые диалоги — по существующим паттернам модалок, с focus trap и Escape.
- Новые backend-команды — `cmd_*`, регистрация в `commands/mod.rs` и `lib.rs`.
- Новые пути — только через backend, с canonicalize и проверкой разрешённой директории.
- Новые ошибки — с кодом, понятным сообщением и действием; без секретов.
- Новые зависимости — только при доказанной необходимости; проверять лицензии и размер бандла.

### Что не делать

- Не возвращать RoomSync/Room Sharing.
- Не смешивать Java- и Bedrock-запуск в одном модуле.
- Не добавлять произвольный CSS/JS-инъекции ради тем.
- Не писать в `custom_skins` Bedrock без документированного формата.
- Не использовать сторонние загрузчики Bedrock.
- Не менять версии/CI/релизные файлы в рамках этих планов.

## 5. Условия старта

Перед реализацией любого направления:

- [ ] Владелец подтвердил границы MVP из соответствующего документа.
- [ ] Базовые проверки зелёные: `npx tsc --noEmit`, `npm test`, `cargo check`, `cargo test`.
- [ ] Нет незакоммиченных изменений в чужих файлах; рабочее дерево понятно.
- [ ] Для skin: есть тестовый Microsoft-аккаунт, на котором допустима загрузка скина; проверены offline/Ely.by-сценарии; секреты не попадают в репозиторий.
- [ ] Для theme: проведён аудит токенов и захардкоженных цветов; набор 22 ключевых токенов и модель одного слота зафиксированы.
- [ ] Для Bedrock: проведён spike на машине с официальной игрой; проверены Store/trial ссылки; согласована юридическая плашка.
- [ ] Для Bedrock: есть машина без игры для проверки пустого состояния.
- [ ] Определён ответственный за ручной E2E-тест на Windows.

## 6. Критерии MVP

### Skin Editor

- Открывается из карточки Microsoft, offline или Ely.by; показывает текущую/стартовую текстуру.
- Импорт PNG 64×64 с компьютера; 64×32 отклоняется с понятным сообщением.
- Рисование/стирание/заливка/пипетка, undo/redo, base/outer.
- Classic/slim, 3D-превью обновляется.
- Загрузка в Minecraft работает; после неё обновляются превью и голова.
- Ошибки загрузки/импорта понятны, draft не теряется; секреты не логируются.
- Экспорт PNG работает; offline/Ely.by не предлагают upload.
- Постоянные черновики и локальная библиотека скинов не создаются.
- Нет регрессий в Accounts/Home.

### Theme Editor

- Ровно одна пользовательская тема на основе встроенной; 22 ключевых токена.
- Предпросмотр на реальных классах, предупреждения контраста.
- Сохранение/применение/перезапуск; сброс к базовой и отключение темы.
- Импорт/экспорт JSON с строгой валидацией; импорт не может выполнить CSS/JS-инъекцию.
- Liquid Glass полностью перекрывает custom-тему и возвращает её после отключения.
- Нет вспышки темы при старте.
- Библиотека нескольких тем в MVP отсутствует.
- Нет регрессий в Settings/Liquid Glass.

### Bedrock

- Страница доступна без установленной игры.
- На машине без игры — понятное пустое состояние и официальные ссылки.
- На машине с игрой — версия/PFN/AUMID и запуск.
- Ошибки содержат код и действие.
- Нет скачивания игры, обхода лицензии, изменения пакета.
- FS-доступ ограничен package data; произвольный путь из frontend невозможен.
- Юридическая плашка видима.
- Нет регрессий в Java-запуске.

## 7. Риски верхнего уровня

| Риск | Направление | Что делать |
|---|---|---|
| API скинов изменится | Skin | Изолировать в `auth.rs`, тесты, понятные ошибки |
| Кэш голов покажет старый скин | Skin | Инвалидировать после upload |
| Импорт PNG повредит текущий draft | Skin | Валидация до замены, подтверждение, draft не меняется при ошибке |
| Захардкоженные цвета | Theme | Аудит этапа 0 |
| Плохой контраст | Theme | WCAG-проверки, блокировка критических пар |
| Светлая тема ломает нативные контролы | Theme | MVP только dark |
| Потеря единственной темы в localStorage | Theme | Экспорт, предупреждение, позднее зеркало |
| Импорт затирает текущую тему | Theme | Подтверждение замены, валидация до записи |
| AUMID/PFN отличаются | Bedrock | Вычислять, не хардкодить |
| PowerShell отключён | Bedrock | Native fallback |
| Helper вместо игры | Bedrock | Не обещать running state до spike |
| Формат миров/скинов хрупок | Bedrock | Read-only, лимиты, без записи |
| Backup во время игры повреждён | Bedrock | Предупреждение/блокировка, safety-копия |
| Юридические претензии | Bedrock | Только официальный запуск, EULA, плашка |
| Расползание объёма | Все | Строго MVP, advanced отдельно |
| Конфликты i18n/Settings | Все | Последовательная реализация, общие ключи |

## 8. Открытые решения для владельца

По редактору скинов и редактору тем открытых вопросов на уровне MVP нет: skin открывается полноэкранным диалогом из карточки аккаунта; theme — одна тема, 22 токена, импорт/экспорт, сброс, отключение и Liquid Glass зафиксированы. Ниже остались только вопросы по Bedrock, которые не блокируют документы, но должны быть закрыты до его реализации:

1. **Bedrock:** отдельная страница или карточка в Home?
2. **Bedrock:** входят ли миры и backup в MVP или это этап 2?
3. **Bedrock:** нужна ли отдельная кнопка trial?
4. **Bedrock:** нужен ли running state или достаточно «Запустить»?
5. **Bedrock:** нужна ли явная поддержка ARM64/Windows 10?
6. **Bedrock:** нужен ли read-only браузер `custom_skins`/`skin_packs`?

## 10. Проверка актуальности

Дата подготовки: октябрь 2026. Версия проекта: `1.3.0`.

Перед реализацией перепроверьте:

- актуальные версии `skinview3d`, Tauri, `tauri-plugin-opener`;
- официальные URL Minecraft Store/trial/EULA;
- наличие `windows` crate и его фич, если переходить на native detection;
- актуальные CSS-токены после изменений темы;
- что `heads` всё ещё кэширует по UUID, а `cmd_change_skin` не инвалидирует кэш;
- что `custom_skins` Bedrock всё ещё не имеет документированного формата.

Если факты изменились, обновите соответствующий план, а не подгоняйте код под устаревший документ.
